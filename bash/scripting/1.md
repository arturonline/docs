# scripts

## script creation

```bash
#!/usr/bin/env bash
# The shebang must be the very first line. `env` finds bash in the PATH
# (useful on macOS/BSD where /bin/bash is old or bash lives elsewhere).

# comment
```

```bash
chmod u+x my_script.sh
```

## running a script

| Command                 | Effect                                                                  |
| ----------------------- | ----------------------------------------------------------------------- |
| `./my_script.sh`        | runs in a new process using the shebang (needs `+x`)                    |
| `bash my_script.sh`     | runs in a new bash process (no `+x` or shebang needed)                  |
| `source my_script.sh`   | runs in the **current** shell (`. my_script.sh` in POSIX); variables, `cd` and `exit` affect your shell |
| `bash -n my_script.sh`  | syntax check only                                                       |
| `bash -x my_script.sh`  | trace: print each command before running it (`set -x` / `set +x` inside) |

💡 Put your scripts in a directory in your `PATH` to call them by name, see [path](../utils/path.md). Lint them with [ShellCheck](https://www.shellcheck.net/): `shellcheck my_script.sh`.

## script result

In the shell, every command has a return status which is either 0 indicating success or an integer (1-255) indicating failure. The status of a script is that of `exit N`, or of the last command executed. See [flow control](../flow_control.md#exit).

```bash
./my_script.sh; echo "status: $?"
./my_script.sh && echo "ok" || echo "failed"
```

## Positional parameters

| parameter | action                                                       |
| --------- | ------------------------------------------------------------ |
| `$0`      | script name                                                  |
| `$1 - $9` | positional argument (`${10}`, `${11}`... need braces)        |
| `$#`      | arguments number                                             |
| `$*`      | all arguments; `"$*"` joins them in one string               |
| `$@`      | all arguments; unquoted it splits words (better use `"$@"`)  |
| `"$@"`    | all arguments, each one as a separate word                   |
| `$?`      | result of the last execution                                 |
| `$$`      | PID of the process is running                                |
| `$!`      | PID of the last background process                           |

`"$@"` expands each positional parameter to a separate word, which makes it perfect for taking command line or function arguments in and then passing them on to another command or function. And because it expands using double quotes, it means things don't break if, say, `"$1"` contains a space or an asterisk `*`.

```bash
# ./args.sh "a b" c
echo "$#"          # 2
echo "$1"          # a b
shift              # drop $1; now $1=c
echo "$# $1"       # 1 c
echo "${1:?missing argument}"   # aborts with an error if $1 is empty/unset
```

## strict mode

```bash
set -euo pipefail
```

| Option            | Effect                                                             |
| ----------------- | ------------------------------------------------------------------ |
| `-e` (errexit)    | exit when a command fails                                          |
| `-u` (nounset)    | error on unset variables (`${var:-default}` still works)           |
| `-o pipefail`     | a pipeline fails if **any** command fails, not only the last one   |

⚠ Caveats, `set -e` is not a safety net:

- It is ignored inside `if`, `while`, `&&`, `||` conditions, **and in any function called from them**: in `f || echo failed`, a failing command inside `f` does not stop `f`.
- `(( i++ ))` when `i` is 0 returns 1 and kills the script. Use `(( ++i ))` or `i=$((i + 1))`.
- `local v=$(cmd)` / `export v=$(cmd)` hide the failure of `cmd`. Declare first, then assign.
- With `pipefail`, `cmd | head -1` may fail (status 141, SIGPIPE) when `cmd` keeps writing after `head` exits.
- `grep` returns 1 when nothing matches: `count=$(grep -c foo file || true)`.

Check errors explicitly where it matters: `cd "$dir" || exit 1`.

## cleanup with trap

```bash
tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT                         # always runs on exit (normal, error or Ctrl-C)
trap 'echo "error on line $LINENO" >&2' ERR       # runs when a command fails
trap 'echo "interrupted"; exit 130' INT          # Ctrl-C
```

## options with getopts

```bash
#!/usr/bin/env bash
set -euo pipefail

usage() {
    echo "Usage: ${0##*/} [-v] [-n name] file..." >&2
    exit 2
}

verbose=0
name="world"
while getopts ":vn:h" opt; do          # ':' after a letter = requires an argument
    case $opt in
        v) verbose=1 ;;
        n) name=$OPTARG ;;
        h) usage ;;
        :) echo "Option -$OPTARG requires an argument" >&2; usage ;;
        \?) echo "Unknown option: -$OPTARG" >&2; usage ;;
    esac
done
shift $((OPTIND - 1))                  # now "$@" contains only the files

(( $# > 0 )) || usage

if (( verbose )); then echo "verbose on, $# file(s)"; fi
echo "Hello, $name: $*"
```

```bash
$ ./greet.sh -v -n Ana a.txt b.txt
verbose on, 2 file(s)
Hello, Ana: a.txt b.txt
$ ./greet.sh -x a
Unknown option: -x
Usage: greet.sh [-v] [-n name] file...
$ echo $?
2
```

`getopts` only supports short options (`-v`). For long options (`--verbose`) loop over `"$@"` with `case` and `shift`, or use GNU `getopt`.

## useful snippets

```bash
script_dir=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)   # directory of the script
echo "error: something failed" >&2                                # messages to stderr
[[ $EUID -eq 0 ]] || { echo "run as root" >&2; exit 1; }           # require root
command -v jq >/dev/null || { echo "jq is required" >&2; exit 1; } # require a tool
[[ ${BASH_SOURCE[0]} == "$0" ]] && main "$@"                      # run main only if not sourced
```
