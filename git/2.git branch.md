# Branching

See also: [Git basics](1.git.md) · [Remotes](3.Remote.md)

## Introduction

When you create a branch in your project, you're creating an environment where you can try out new ideas. Changes you make on a branch don't affect the main branch, so you're free to experiment and commit changes, safe in the knowledge that your branch won't be merged until it's ready to be reviewed by someone you're collaborating with.

A branch is just a movable pointer to a commit. `HEAD` points to the branch you are on.

### List

```bash
# list all local branches (* = current)
git branch

# list local and remote-tracking branches
git branch -a

# only remote-tracking branches
git branch -r

# with last commit and upstream info: [origin/main: ahead 1, behind 2]
git branch -vv

# branches already merged / not merged into the current one
git branch --merged
git branch --no-merged
```

### Create a new branch

```bash
# Create a new branch called "new_branch" (stays on the current one)
git branch new_branch

# Create it from another branch, tag or commit
git branch new_branch v1.2.0
```

```bash
# Delete a branch (only if it is merged)
git branch -d new_branch

# Force delete the specified branch (unmerged work is lost, but see "reflog" in 1.git.md)
git branch -D new_branch
```

```bash
# Rename the current branch
git branch -m new_name

# Rename another branch
git branch -m old_name new_name

# Rename master to main
git branch -m master main
```

### Navigate between branches

`git switch` (Git 2.23+) lets you navigate between the branches created by `git branch`. Switching to a branch updates the files in the working directory to match the version stored in that branch, and it tells Git to record all new commits on that branch. Think of it as a way to select which line of development you're working on.

The classic command is `git checkout`, which does the same but also restores files; `switch` (branches) and `restore` (files) split those two jobs.

```bash
# Switch to branch "new_branch"
git switch new_branch          # classic: git checkout new_branch

# Back to the previous branch
git switch -

# Create and switch to a new branch
git switch -c new_branch       # classic: git checkout -b new_branch

# Create it from a specific starting point
git switch -c hotfix origin/main

# Check out a remote branch (creates a local tracking branch automatically)
git switch feature-x           # if origin/feature-x exists

# Inspect an old commit without a branch ("detached HEAD")
git switch --detach a1b2c3d
```

When you want to start a new feature, you create a new branch off `main` and switch to it with `git switch -c new_branch`. You can work on multiple features in a single repository by switching between them (or in parallel folders with `git worktree`, see [Git basics](1.git.md#worktree-several-branches-checked-out-at-once)).

> Uncommitted changes travel with you when you switch. If they conflict with the target branch, Git refuses: commit or `git stash push` first.

## Merging Changes

When you're done with the development branch, the next step is to merge it into the `main` branch.

```bash
# First change to the main branch (and update it)
git switch main
git pull

# Merge the new_branch branch into main
git merge new_branch

# Delete the old branch
git branch -d new_branch
```

Types of merge:

- **Fast-forward**: `main` has no new commits, so Git just moves the pointer forward. No merge commit.
- **Three-way merge**: both branches have new commits, Git creates a merge commit with two parents.

```bash
git merge --no-ff new_branch   # always create a merge commit (keeps the branch visible in history)
git merge --ff-only new_branch # only merge if it can fast-forward, fail otherwise
git merge --squash new_branch  # put all the changes in the staging area as ONE commit (then git commit)
git merge --abort              # cancel a merge with conflicts
```

How to resolve conflicts: see [Resolve a merge conflict](1.git.md#resolve-a-merge-conflict).

## Rebase

Rebase moves your commits on top of another branch, re-creating them one by one. The result is a linear history without merge commits.

```text
Before:                     After "git rebase main" on feature:
      A---B  feature                          A'--B'  feature
     /                                       /
C---D---E  main                C---D---E  main
```

```bash
git switch feature
git rebase main             # replay feature's commits on top of main

# if there are conflicts: fix the files, then
git add file.txt
git rebase --continue
git rebase --skip           # drop the current commit
git rebase --abort          # back to how it was before the rebase
```

> Golden rule: **don't rebase commits that other people already have** (pushed to a shared branch). If you rebase your own pushed branch, push with `git push --force-with-lease`.

### Interactive rebase: clean up history before sharing

```bash
git rebase -i HEAD~3        # edit the last 3 commits
git rebase -i main          # edit all commits of the branch not in main
```

The editor shows a list (oldest first). Change the word at the start of each line:

```text
pick   a1b2c3d Add login form
squash e4f5a6b Fix typo          # merge into the previous commit, edit the message
fixup  c7d8e9f Forgot a file     # merge into the previous commit, discard this message
reword 0a1b2c3 Add validaton     # change the message
edit   4d5e6f7 Big commit        # stop here to amend / split it
drop   8a9b0c1 Debug prints      # delete the commit
```

Lines can also be reordered. Save and close to apply.

### fixup! commits + autosquash

Fix an older commit without editing the list by hand:

```bash
git commit --fixup=a1b2c3d     # creates "fixup! Add login form"
git rebase -i --autosquash main
# the fixup line is already moved under a1b2c3d and marked as "fixup"

git config --global rebase.autoSquash true   # make --autosquash the default
```

## Cherry-pick

Copy one or more commits from another branch onto the current one:

```bash
git cherry-pick a1b2c3d           # apply that commit here (new hash)
git cherry-pick a1b2c3d e4f5a6b   # several
git cherry-pick A..B              # range (A excluded)
git cherry-pick -x a1b2c3d        # add "(cherry picked from commit ...)" to the message
git cherry-pick --no-commit a1b2c3d   # apply the changes without committing

# conflicts: fix, git add, then
git cherry-pick --continue        # or --abort
```

Typical use: bring a hotfix from `main` to a release branch.

## Common workflow

```bash
git switch main && git pull
git switch -c feature/login
# ... work, commit, commit ...
git fetch origin
git rebase origin/main            # stay up to date (or: git merge origin/main)
git push                          # with push.autoSetupRemote; otherwise git push -u origin feature/login
# open a Pull Request, after it is merged:
git switch main && git pull
git branch -d feature/login
```
